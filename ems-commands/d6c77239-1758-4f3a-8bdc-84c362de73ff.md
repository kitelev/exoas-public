# Partially Done: close current partially + spawn next iteration

The grounding behind the `ems__Task` «Partially Done» command (`fefb9f38`, req
`87361a62`). A `composite` of five steps. Step 1 clones the clicked task into the
next iteration; steps 2-5 close the CURRENT (clicked) task as **done-but-partial**:

1. **`1abb0211`** (`create_instance`) — create the next iteration cloning the
   current task (label / area / parent / zone / relates / deadline / estimate /
   body), status Backlog, `prevIteration` → current.
2. **`bdf3c81f`** (`property_set`) — mark the CURRENT task `ems__Effort_status`
   = Done. Reuses the shared «Set status to Done» step (same one «Mark Done»
   uses).
3. **`b2ba56b9`** (`property_set`) — set the CURRENT task
   `ems__Effort_endTimestamp` = `$nowLocal`. Reused shared step.
4. **`ee5c36a3`** (`property_set`) — set the CURRENT task
   `ems__Effort_resolutionTimestamp` = `$nowLocal`. Reused shared step.
5. **`6dede0b0`** (`property_set`) — set the CURRENT task
   `ems__Effort_partiallyDone` = `true` — the honest partial-close marker.

Steps 2-4 reuse the same standard timestamp-stamping groundings the built-in «Set
Status Done» composite (`77be16d6`) uses, so a partially-closed task records its
duration honestly. Step order is create-then-close so the clone reads the current
task while it is still pristine (Doing) — all `property_set` steps target the
click-target, not the created file (only `body_template` steps thread the created
path). On any step failure the composite rolls back the click-target's content.
