# ems__WaitingCheckTask

GTD «Waiting For» as a first-class **iterative check task** (design spec `51b249c7`,
req `915b20b2`, user interview 2026-06-30).

Direct subClass of `ems__Task` (`1b20a8f0`) — inherits the whole Task lifecycle
(status workflow start-effort / mark-done / move-to-backlog resolves via subclass
workflow inheritance, req 915b20b2) plus every Task/Effort property.

A `WaitingCheckTask` models "I am waiting for an external answer and there is
nothing to DO yet except check again tomorrow". On the day it is planned, the
homoiconic **«Следующая итерация»** by-class button (binding `ed83a97b`) closes the
current check (→ Done) and spawns the next iteration — a clone of the current one
(same label, zone, parent, relates, body; new uid/createdAt; status Backlog;
`ems__Effort_plannedStartTimestamp` = tomorrow, a soft daily tickler;
`ems__Effort_prevIteration` → the closed check). The chain ends with an ordinary
mark-done (no next iteration) = «waited / answer arrived».

- **How many checks it took** = length of the `ems__Effort_prevIteration`
  (`3104b383`) chain — query-derived, no counter property (Vision Lock 6).
