# ems__Reminder_afterEffort

Задача, по завершении которой приходит напоминание («когда закончу — напомни»). Напоминание с этим свойством ставится БЕЗ `ems__Reminder_at`: время срабатывания неизвестно заранее. Исполнитель — reminder-checker: на каждом опросе он смотрит, закрыта ли задача, и, увидев закрытие, отправляет напоминание с припиской «↳ после «<задача>»»; только после успешной отправки он записывает `ems__Reminder_at` = момент отправки, и дальше это обычное напоминание (отметка «отправлено», отсрочка кнопкой, «✅ Готово»). Неотправленное (нет адресата, отказ Telegram) остаётся ждущим.

«Закрыта» — статус Done или Trashed либо стоит `ems__Effort_endTimestamp` (тот же смысл, что у `ems__Effort_blocker`; YAML-null фактом не считается). Статус судится по UID ссылки, а не по подписи после `|`.

Значение — вики-ссылка на задачу по её UID (`exo__Asset_uid`). Ссылку по метке граф принимает, но исполнитель ищет задачу по UID — такое напоминание не придёт; обёртка личного бота её отвергает.

Пример: «когда закончу тренировку, напомни выпить воды» — напоминание с текстом «выпить воды», без `ems__Reminder_at`, где это свойство ссылается на текущую задачу «тренировка» (значение — вики-ссылка на её UID).

Ограничения:

- исполнитель читает хранилище бота, а оно подтягивает изменения перед ответом бота: задачу закрыли НЕ через бота (Obsidian, другое устройство) — напоминание придёт при следующем ходе бота, иногда через часы; тогда приписка называет время закрытия;
- задача была закрыта ещё до того, как поставили напоминание, — оно приходит сразу с предупреждением «⚠ … проверь, та ли задача»;
- задача ищется по имени файла `<uid>.md` в хранилище бота: файл, названный не её uid, не найдётся;
- если у напоминания уже есть `ems__Reminder_at`, срабатывает оно по времени, а это свойство не используется;
- включается для бота отдельно (`REMIND_AFTER_BOTS` у reminder-checker); вне гейта такое напоминание не отправляется, и это записывается в журнал демона.

Отменить ждущее напоминание — записать `ems__Reminder_doneAt`.
