# ems__Bug_defectClass

Короткая **машинная метка класса дефекта** продукта-ассистента: стабильный идентификатор из
фиксированного набора, а не свободное описание. Хранится строкой (`xsd:string`).

## Зачем метка, если есть название бага

Название пишет модель и оно каждый раз новое. Метка нужна двум механизмам, которым нужна
**стабильность**, а не читаемость:

- **Счёт возвратов.** Вернувшийся дефект приезжает НОВЫМ ассетом с новым UID и без связи с
  предшественником, поэтому по UID он неотличим от нового и «улучшает» статистику. Счёт ведётся по
  нормализованному классу (тот же приём, что счёт клонов по хешу метки в петле поставки).
- **Регрессионный набор.** Воспроизводящий вопрос каждого закрытого бага остаётся в постоянном
  наборе, который гоняется на следующих фиксах; ключ набора — класс, не UID.

## Набор значений (расширяется по мере появления классов)

| Метка | Что означает |
|---|---|
| `search-wordform` | поиск по графу не переживает словоформу русского языка (метка «Посмотре**ть**» против запроса «просмотр») |
| `search-false-negative` | уверенное «не нашёл» там, где ассет существует, — при неверной форме запроса, а не отсутствии данных |
| `wrong-property` | выдумано или перепутано имя свойства/класса при мутации |
| `wrong-asset` | правка/создание применены не к тому ассету |
| `duplicate-created` | заведён дубль вместо переиспользования существующего |
| `status-machine` | неверный переход статуса либо отказ команды принят за ошибку |
| `answer-not-grounded` | ответ не опирается на то, что реально найдено в графе |
| `other` | класс ещё не выделен; выделяется при втором появлении |

⛤ Набор **фиксирован в персоне продукта**: бот выбирает из него, а не сочиняет новую метку. Нет
подходящей — `other`, и это сигнал, что пора завести класс.
