**Profile** (`exo__Profile`) — vault-декларированная **группа AssetSpace** для runtime-материализации. Определяет, какие ассетспейсы физически смонтированы на устройстве.

## Зачем
Решает 4 проблемы:
- **iPhone reindex ~10 мин** → монтировать только нужные AssetSpace, а не весь vault.
- **Cognitive load** от нерелевантных ассетов в SPARQL/поиске.
- **Privacy boundary** — sensitive AssetSpace физически ОТСУТСТВУЮТ на диске вне активного профиля (не «скрыты», а не смонтированы).
- **Coupling** без явных imports между наборами знаний.

## Как работает
Одна операция `Cmd+P → Exocortex: Apply profile` → **mount-state strict replace**: материализует effective set, размонтирует остальное; TS-floor (`$exo`) никогда не размонтируется.

**Effective set** = `includes ∪ transitive(imports*) ∪ TS-floor`.

Активный профиль хранится per-device в `data.local.json` (исключён из Sync через `.local.` infix — выбор профиля не реплицируется между устройствами).

## Аналогия SDK
exo = платформа/SDK · **AssetSpace = jar** · **Profile = BOM** (bill of materials: `_includes` ≈ `dependency`, `_imports` ≈ BOM-`import`).

Материализованность выводится из файловой системы (`exo__AssetSpace_materialized`), а не хранится.
