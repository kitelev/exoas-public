# strategy__Initiative_refines

## Semantics

An initiative **refines** (is a sub-goal of) another initiative — the KAOS goal-refinement
relation applied inside the strategy layer. It makes the initiative hierarchy that today
survives only in label numbering (`I1` → `I1.4`) explicit in the graph, so a rename or a
re-org can no longer lose it silently.

- **Direction:** child → parent (UWI). The refining initiative carries the wikilink to the
  initiative it refines. The inverse is derived by SPARQL, never authored.
- **Cardinality 0..N (a DAG, not a tree):** an initiative may refine several parents
  (KAOS traceability), and an initiative with no parent is a legitimate root — absence is
  never a violation. Transitive traversal via the property-path
  `?init strategy:Initiative_refines+ <root-file-IRI>`.
- **Acyclicity** is a semantic expectation of refinement, not a declared SHACL constraint
  (deliberately deferred — YAGNI; the engine's property-path `+` terminates safely).

Sibling of `strategy__Initiative_pillar` (Initiative → Pillar) and
`strategy__Pillar_strategy` (Pillar → Strategy): together they carry the upward chain from a
concrete initiative to the Vision layer. Mirrors the in-house polymorphic-refinement
precedent `ems__Effort_parent` and the same-layer `req__Requirement_refines`.

Introduced by onto-RFC `f52be424-b089-4a26-ada3-ce2674139876` (Goal-Refinement Continuum,
G1 Phase 1).
